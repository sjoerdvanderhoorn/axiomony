How tools are authorized

Tool discovery changes with the authenticated PostgreSQL account. A tool may be hidden if the user lacks its general operation type; even if visible, every actual database operation is still subject to PostgreSQL roles, table and column grants, row-level security, constraints and triggers.

i

Tool visibility is not permission to access every record. For example, SELECT access to one table may expose select_records, but the user cannot use it to read another table without the required database privileges.

Core and data tools

Every authenticated account can discover whoami, list_tables, describe_table, explain_permissions and app_integration_guide. Data operations appear when the account has the corresponding privilege somewhere in the database. Filters are structured, not arbitrary SQL, and updates/deletions require filters and cap affected rows.

For cell-level business logic, PostgreSQL may still reject an operation in a trigger or policy after the tool becomes visible. explain_permissions describes the relevant rules but does not execute risky test writes.

Administrator tools

A user must be a PostgreSQL superuser or a member of the mcp_admin role to see administration tools. Membership in mcp_admin alone does not grant unrestricted DDL privileges. Real modifications run under the administrator’s PostgreSQL permissions.

Plans are per administrator and expire after 20 minutes by default. You can also call cancel_plan. No schema change is made at the planning stage.

Optional static hosting tools

Set Standalone deployment to start the Nginx static host and expose the six site_* tools. Every authenticated user can manage only the folder associated with their verified PostgreSQL username. Projects may have nested css/, js/, assets/ and other allowed paths.

Uploaded files are public to visitors who can access the static URL. There is no per-viewer authentication on Nginx in this version. Creating or updating a site does not grant browser-side access to PostgreSQL.

Legacy REST helpers

REST_MCP_TOOLS=false by default. When explicitly enabled, Axiomony exposes three PostgREST helper tools for existing integrations. These tools do not replace database authorization, and new task-specific AI-generated applications should prefer Data MCP through a trusted runtime.
