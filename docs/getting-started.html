Install Axiomony

Start locally with bundled PostgreSQL, or connect an external PostgreSQL server. No frontend or separate rule engine required.

On this pageRequirementsBundled PostgreSQLExternal PostgreSQLConfigurationHealth checkStatic hostingTesting

Before you begin

This guide covers the current v0.5.1 development prototype. Choose bundled PostgreSQL for the fastest local start, or connect Axiomony to an existing PostgreSQL server.

!

Prototype only. The MCP endpoint is bound to localhost by default. Do not publish it directly on the internet; it currently uses HTTP Basic with reusable PostgreSQL credentials.

  • Docker Engine and Docker Compose for the container setup.
  • Git to clone the repository (or download its source archive).
  • Node.js 22+ only if you also want to run the code outside Docker.
  • An OPENAI_API_KEY only if you want natural-language database administration.

Option A · Bundled PostgreSQL

Recommended for your first local experiment. Docker starts Axiomony, PostgreSQL 17 and the compatibility PostgREST service. Data is stored persistently in a Docker volume.

Terminal · macOS / Linux / WSL
git clone https://github.com/sjoerdvanderhoorn/axiomony.git
cd axiomony
cp .env.example .env
# Edit .env and set PGDATABASE to your desired database name.
# Optionally set OPENAI_API_KEY to enable admin AI planning.
./scripts/start.sh bundled

On the first start, the startup script creates a random password in .local/postgres_bootstrap_password. Only the PostgreSQL container receives it through a Docker secret. The MCP container does not receive a central database password.

Show local bootstrap credentials
./scripts/show-credentials.sh
# Displays the local bootstrap username: platform_admin
# and the randomly generated PostgreSQL password.
!

Treat the bootstrap account carefully. platform_admin is a PostgreSQL superuser suitable only for controlled local experimentation. Create restricted roles for regular users; do not use this account for everyday work.

Option B · Existing PostgreSQL

Use this option if your database runs on another machine or service. Configure only the host, port and database name in .env; users still authenticate with their own PostgreSQL login at request time.

External database setup
git clone https://github.com/sjoerdvanderhoorn/axiomony.git
cd axiomony
cp .env.example .env
# Set PGHOST, PGPORT, PGDATABASE and PGSSL in .env.
./scripts/bootstrap-external-rest.sh YOUR_DBA_USERNAME
./scripts/start.sh external

The one-time bootstrap prompts interactively for DBA credentials to prepare the limited PostgREST authenticator used by the compatibility service. The MCP service itself stores no shared database account. Your PostgreSQL server must accept connections from the MCP container. Configure secure host-based authentication, preferably SCRAM-SHA-256; do not use trust on remotely reachable connections.

Check the installation

The default installation publishes the MCP service on the local machine only.

Health check
curl http://127.0.0.1:3000/health
# Expected: {"status":"ok","service":"axiomony"}

Then continue to Connect an AI client to learn how PostgreSQL logins, HTTP Basic and MCP requests work.

Optional static app hosting

Set APP_HOSTING_ENABLED=true in .env and run the start script again. An existing nginx/nginx-unprivileged image serves each user’s published HTML, CSS and JS beneath their verified PostgreSQL username, such as /apps/alice/invoices/index.html.

.env · optional hosting
APP_HOSTING_ENABLED=true
APP_PUBLIC_URL=http://localhost:8088
APP_BIND_ADDRESS=127.0.0.1
APP_PORT=8088

Without the flag, no Nginx hosting container starts and the six site_* MCP tools are not advertised. Published pages are publicly readable to anyone who can reach the hosting URL, although file editing requires the user’s database login.

i

Static hosting is not a backend. Standalone HTML/JavaScript cannot safely authenticate directly with PostgreSQL. The secure browser-session and Data-MCP runtime bridge is not part of this version.

Run the unit tests

Local Node.js tests
npm install
npm test

The repository includes unit tests but has not been verified end-to-end with actual running Docker, PostgreSQL, Nginx and a hosted AI client. See security and limitations before trying production data.
